| | Deskripsi |
| ----------- | ----------- |
| Dataset | [Heart Disease (UCI)](https://www.kaggle.com/datasets/redwankarimsony/heart-disease-data) — 920 baris rekam medis gabungan dari 4 rumah sakit (Cleveland, Hungary, Switzerland, VA Long Beach), berisi 13 atribut klinis klasik (usia, tekanan darah, kolesterol, hasil EKG, dsb.) plus label tingkat keparahan penyakit jantung. |
| Masalah | Penyakit jantung adalah salah satu penyebab kematian tertinggi, dan deteksi dini risikonya penting agar penanganan medis bisa dilakukan lebih cepat. Diagnosis dini biasanya membutuhkan pemeriksaan lanjutan yang mahal/invasif, padahal sebagian besar sinyal risiko sudah bisa ditangkap dari atribut klinis dasar (usia, tekanan darah, kolesterol, hasil EKG, dll). |
| Solusi machine learning | Membangun model klasifikasi biner yang memprediksi apakah seorang pasien berisiko penyakit jantung (`target = 1`) atau tidak (`target = 0`) dari 13 atribut klinis dasar. Seluruh proses — mulai dari validasi data, feature engineering, training, evaluasi, sampai model siap di-serve — dirangkai sebagai satu **machine learning pipeline** otomatis memakai TensorFlow Extended (TFX) dengan Apache Beam (`BeamDagRunner`) sebagai orchestrator, sehingga proses bisa diulang secara konsisten setiap kali ada data baru. Target keberhasilan: model lolos threshold **AUC ≥ 0.65** pada komponen `Evaluator` sebelum diizinkan di-push ke serving. |
| Metode pengolahan | Label asli `num` (0–4, tingkat keparahan) dibinerkan menjadi `target` (0 = sehat, 1 = berisiko); kolom `id` dan `dataset` (asal rumah sakit) dibuang karena bukan fitur klinis dan berpotensi *leakage*. Missing value (`ca` 66%, `thal` 53%, `slope` 34%, sisanya <10%) diimputasi **sekali di luar graph TFX** oleh `modules/data_preparation.py` (median untuk numerik, kategori `"missing"` untuk kategorikal) menghasilkan `data_clean/heart_disease_clean.csv`. Di dalam pipeline: `CsvExampleGen` membagi data train:eval = 8:2 (hash-bucket, deterministik), lalu `Transform` (`tf.Transform`) melakukan `scale_to_z_score` untuk 6 fitur numerik dan `compute_and_apply_vocabulary` (dengan `num_oov_buckets=1`) untuk 7 fitur kategorikal, dibekukan ke `transform_graph` agar preprocessing saat training dan serving identik (menghindari *training-serving skew*). |
| Arsitektur model | Model Keras *functional API*: 6 fitur numerik masuk langsung sebagai input; 7 fitur kategorikal masing-masing dilewatkan ke layer `Embedding` (dimensi `min(8, ukuran vocabulary)`) lalu `Flatten`. Seluruh vektor di-*concatenate* (30 dimensi) → `Dense(64, relu)` → `Dropout(0.3)` → `Dense(32, relu)` → `Dropout(0.3)` → `Dense(1, sigmoid)` (total **4.207 parameter**). Optimizer Adam (lr 1e-3), loss `binary_crossentropy`, dengan `EarlyStopping` (monitor `val_auc`, patience 5, `restore_best_weights=True`) untuk mencegah overfitting. Signature `serving_default` menerima **raw `tf.Example`** terserialisasi dan menerapkan `transform_features_layer` di dalamnya, sehingga klien serving tidak perlu melakukan preprocessing manual. |
| Metrik evaluasi | Evaluasi memakai **TensorFlow Model Analysis (TFMA)** dengan metrik `ExampleCount`, `BinaryAccuracy`, `Precision`, `Recall`, dan `AUC`, dihitung untuk keseluruhan data eval **dan** per-slice fitur `sex` (mengecek apakah performa timpang antar jenis kelamin). Model dinyatakan **blessed** oleh `Evaluator` hanya jika `AUC ≥ 0.65` (`value_threshold`) dan tidak turun lebih dari 0.001 dari model baseline sebelumnya (`change_threshold`, via `Resolver`/`LatestBlessedModelStrategy`) — hanya model blessed yang diteruskan ke `Pusher`. |
| Performa model | Hasil run pipeline pada data eval (184 baris): **AUC 0.9342**, `binary_accuracy` 0.8804, `precision` 0.8899, `recall` 0.9065, `loss` 0.3184 — jauh di atas threshold 0.65, sehingga model dinyatakan **BLESSED** dan berhasil di-*push* oleh `Pusher` ke `serving_model/naufal_falah_a-pipeline/`. Per-slice `sex`: AUC kedua slice sebanding (`Male` n=143, AUC 0.9247; `Female` n=41, AUC 0.9286), tetapi `recall` pada `Male` (0.9247) jauh lebih tinggi dibanding `Female` (0.7857) — recall yang lebih rendah pada slice `Female` mengindikasikan disparitas performa antar gender yang perlu terus dipantau (lihat bagian Monitoring). |
| Opsi deployment | Model di-serve dengan **TensorFlow Serving** dalam container Docker (`Dockerfile` di root), lalu di-deploy ke **Railway** agar dapat diakses publik melalui REST API tanpa perlu menjalankan server sendiri. |
